# Генератор страховых историй

> Опишите смартфон, полис и что случилось — получите связную историю страхового случая
> и прогноз суммы выплаты с пошаговым расчётом.

**Статус:** MVP, тип объекта — смартфоны.
**Принцип:** *модель рассказывает, код считает.*

---

## Название

**Генератор страховых историй** (Insurance Story Generator) — веб-сервис на FastAPI, который
по структурированным данным об объекте страхования, полисе и событии формирует:

1. **текст истории** — связное описание того, что произошло, на русском языке;
2. **прогноз компенсации** — сумму выплаты и все шаги расчёта, из которых она получилась.

---

## Какую задачу решает

### Проблема

Страховым командам и разработчикам страховых систем постоянно нужны правдоподобные примеры
страховых случаев: для тестирования, демонстраций, обучения сотрудников и моделей. Писать их
вручную долго, а если поручить всё языковой модели, она пишет хороший текст, но ошибается
в цифрах: выдумывает суммы, проценты и даты. В страховании такая ошибка недопустима.

### Решение

Задача разделена на два независимых блока, каждый делает то, что умеет лучше всего.

| Блок | Как работает | Почему так |
|---|---|---|
| **Расчёт компенсации** (`calculator.py`) | Детерминированные правила: цена покупки → износ по возрасту → коэффициент состояния → размер ущерба по типу события → ограничение страховой суммой → вычет франшизы | Каждую цифру можно объяснить и проверить; расчёт покрыт тестами |
| **Текст истории** (`story.py`) | Языковая модель пишет повествование по фактам в JSON. Сумм она не получает, итоговое предложение с цифрами добавляет код | Модель хорошо пишет текст, но цифры ей доверять нельзя |

### Как устроен расчёт

- **Износ:** 2 % в месяц в первый год, затем 1 % в месяц, не более 70 %.
- **Состояние:** отличное ×1,0, хорошее ×0,9, удовлетворительное ×0,75.
- **Ущерб по типу события:**
  - повреждение экрана — ремонт ≈ 25 % цены покупки;
  - залитие — ремонт ≈ 60 % цены покупки;
  - кража и полная гибель — текущая стоимость устройства;
  - иное повреждение — текущая стоимость × степень ущерба (0–1).
- **Полная гибель** признаётся, если ремонт дороже 80 % текущей стоимости.
- Затем ущерб ограничивается страховой суммой и уменьшается на франшизу.

Все коэффициенты — стартовые допущения MVP, их нужно калибровать на реальных данных о выплатах.

### Три способа написать текст

| Режим (`STORY_GENERATOR`) | Источник текста | Когда подходит |
|---|---|---|
| `llm` | Claude API | Лучшее качество текста, нужен ключ API и интернет |
| `ollama` | Локальная модель (по умолчанию `qwen3:4b-instruct`) | Бесплатно, без интернета, данные не покидают компьютер |
| `template` | Шаблоны | Всегда доступно, мгновенно |

### Надёжность

- **Приложение отвечает всегда.** Если модель недоступна, нет ключа, произошла ошибка сети
  или модель отказалась отвечать, используется шаблон. Поле `story_source` в ответе показывает,
  откуда взят текст.
- **Проверка ответа локальной модели.** Если в тексте есть суммы, проценты или числа, которых
  нет во входных данных (например, неверная дата), делается вторая попытка, затем — шаблон.
- **Защита от злоупотребления.** Каждый результат помечен как «Сгенерировано автоматически.
  Не является страховым документом», а модели прямо запрещено придумывать ФИО, адреса, номера
  документов и названия реальных организаций. Сгенерированные истории нельзя выдать за
  настоящие заявления о страховом случае.

## Пользователь

### Для кого

| Пользователь | Что получает |
|---|---|
| **Разработчики и тестировщики страховых систем** | Реалистичные синтетические страховые случаи для тестов и демо-стендов вместо ручного заполнения |
| **Аналитики и андеррайтеры** | Быстрый прогноз «сколько будет стоить этот случай» с прозрачным пошаговым расчётом |
| **Специалисты по обучению** | Готовые кейсы для тренировки сотрудников урегулирования убытков |
| **Команды, работающие с ML** | Синтетические данные для обучения моделей, пока нет реальной истории выплат |

### Как пользоваться

1. Дважды щёлкнуть по `start.bat` — сервер запустится, браузер откроется сам.
2. Заполнить форму из трёх блоков:
   - **Объект:** марка, модель, цена и дата покупки, состояние;
   - **Полис:** страховая сумма, франшиза;
   - **Событие:** тип, дата, степень ущерба (для «иного повреждения»).
3. Нажать **«Сгенерировать»** и получить прогноз выплаты, текст истории и таблицу расчёта.

То же доступно через API: `POST /api/claims/estimate`, документация — на `/docs`.

### Чего пользователь не получит

- Это **не** официальный расчёт страховой выплаты и не страховой документ.
- Коэффициенты условные; реальные правила страхования конкретной компании не учитываются.
- Пока поддерживаются только смартфоны.

## Технологии

Python 3.10+, FastAPI, Pydantic, Uvicorn, Anthropic SDK (Claude), Ollama, pytest, HTML без сборки.

## Планы развития

1. Новые типы объектов — следующим этапом автомобили (ОСАГО/КАСКО, калькуляция ремонта, УТС).
2. Хранение истории расчётов (SQLite, позже PostgreSQL).
3. Интерфейс на React/Next.js.
4. Прогноз выплат с помощью машинного обучения — когда появятся реальные данные.
